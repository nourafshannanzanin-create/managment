# مستند جامع آموزش کاربران سامانه کارنومند

## 1. معرفی و دامنه مستند

این مستند بر اساس کد فرانت‌اند و بک‌اند پروژه تهیه شده و برای آموزش کامل استفاده از:

- پنل مدیر
- پنل کاربر
- حساب HQ
- مسیرهای ورود و ثبت‌نام

طراحی شده است.

هدف این فایل این است که بتوان از آن برای:

- تولید ویدئوی آموزشی
- نوشتن راهنمای کاربری
- آموزش اپراتور پشتیبانی
- آموزش مدیران سازمان

استفاده کرد.

## 2. معماری ناوبری و نقش‌ها

### 2.1 مسیرهای اصلی سامانه

| --- | --- | --- |
| ورود | `/login` | ورود کاربر و ثبت‌نام مجموعه |

| درخواست‌ها | `/requests` | ثبت، مشاهده و پیگیری درخواست‌ها |

## 3. اجزای مشترک کل سامانه

### 3.1 سایدبار

المان‌ها:

- نام مجموعه
- منوی اصلی
- badge تعداد آیتم‌های در انتظار در درخواست‌ها، تاییدیه‌ها، هزینه‌ها، پشتیبانی
- دکمه `خروج از سامانه`

عملکردها:

- تغییر route
- نمایش منو بر اساس نقش
- خروج و پاک‌سازی نشست

### 3.2 نوار بالایی

المان‌ها:

- عنوان صفحه
- دکمه منوی موبایل
- انتخاب مجموعه برای HQ
- دکمه‌های سریع هر صفحه
- فیلترهای هدر در صفحات فهرستی

صفحات دارای فیلتر هدر:

- `/requests`
- `/expenses`
- `/approvals`
- `/reports`

فیلترهای هدر:

- جستجو
- شخص
- از تاریخ
- تا تاریخ
- بازنشانی فیلتر

### 3.3 رفتارهای سراسری

| رفتار | توضیح |
| --- | --- |
| احراز هویت | همه routeها به‌جز `/login` نیازمند توکن هستند |
| Loader سراسری | هنگام بارگذاری، ثبت فرم‌ها، لود جزئیات و ذخیره امضا نمایش داده می‌شود |
| هشدار موجودی پیامک | اگر موجودی کیف پول پیامک صفر یا کمتر باشد، بالای محتوا نشان داده می‌شود |
| مودال‌های سراسری | جزئیات درخواست، هزینه، تاییدیه و فرم‌های ساخت از هر صفحه قابل فراخوانی‌اند |

## 4. مسیر ورود و ثبت‌نام

## 4.1 صفحه ورود

| آیتم | مقدار |
| --- | --- |
| نام صفحه | ورود |
| Route | `/login` |
| نقش مجاز | مهمان |
| هدف | ورود به سامانه و ارسال درخواست ثبت‌نام مجموعه |

### المان‌ها

- فیلد `نام کاربری / ایمیل`
- فیلد `رمز عبور`
- چک‌باکس `مرا به خاطر بسپار`
- دکمه `ورود به سیستم`
- دکمه لینک `ثبت نام مجموعه`
- پیام خطا
- پیام موفقیت ثبت‌نام

### عملکرد دکمه‌ها و فیلدها

| المان | عملکرد |
| --- | --- |
| نام کاربری / ایمیل | ورود با `slug` یا ایمیل |
| رمز عبور | ارسال برای API ورود |
| ورود به سیستم | POST به `/auth/login` |
| ثبت نام مجموعه | بازکردن مودال ثبت‌نام |

### اعتبارسنجی‌ها

- خطای ورود نامعتبر: `ایمیل یا رمز عبور نادرست است.`

### پیام موفقیت

- پس از ورود موفق، کاربر به `/dashboard` می‌رود.

### ارتباط با سایر صفحات

- ورود موفق به داشبورد
- ثبت‌نام موفق، بازگشت به همین صفحه با پیام موفقیت

### سناریوی کامل

1. کاربر نام کاربری یا ایمیل را وارد می‌کند.
2. رمز عبور را وارد می‌کند.
3. روی `ورود به سیستم` می‌زند.
4. در صورت موفقیت، نشست ساخته شده و اطلاعات bootstrap بارگذاری می‌شود.
5. کاربر به داشبورد منتقل می‌شود.

### CRUD

- `Create`: ایجاد نشست ورود
- `Read`: ندارد
- `Update`: ندارد
- `Delete`: ندارد

### نکات مهم

- اگر توکن موجود باشد، ورود مجدد به `/login` کاربر را به `/dashboard` برمی‌گرداند.

## 4.2 مودال ثبت‌نام مجموعه

| آیتم | مقدار |
| --- | --- |
| نام مودال | درخواست ایجاد مجموعه |
| فراخوان از | `/login` |
| نقش مجاز | مهمان |
| هدف | ارسال درخواست ثبت‌نام سازمان برای بررسی HQ |

### المان‌ها

- نام مجموعه
- نام مدیر
- نام کاربری مدیر
- ایمیل مدیر
- تلفن مدیر
- رمز عبور مدیر
- آپلود مدارک
- دکمه `ارسال درخواست ثبت نام`
- دکمه `بستن`

### اعتبارسنجی‌ها

- `نام مجموعه، نام مدیر، نام کاربری، تلفن و رمز عبور الزامی است.`
- `رمز عبور باید حداقل ۶ کاراکتر باشد.`
- `بارگذاری حداقل یک مدرک یا تصویر جواز الزامی است.`
- `مدارک فقط باید تصویر یا فایل PDF باشند.`
- `حجم هر مدرک نباید بیشتر از ۱۰ مگابایت باشد.`
- `برای این نام مجموعه قبلاً درخواست ثبت شده است.`
- `این نام کاربری قبلاً استفاده شده است.`
- `این ایمیل قبلاً استفاده شده است.`

### پیام موفقیت

- `درخواست ثبت‌نام و مدارک شما ارسال شد. پس از بررسی پشتیبانی، حساب مجموعه فعال می‌شود.`

### وابستگی‌ها

- ماژول پشتیبانی
- تیکت ثبت‌نام HQ
- عملیات تایید ثبت‌نام در پنل پشتیبانی HQ

### سناریوی کامل

1. کاربر روی `ثبت نام مجموعه` کلیک می‌کند.
2. اطلاعات مجموعه و مدیر را تکمیل می‌کند.
3. حداقل یک فایل مدرک بارگذاری می‌کند.
4. درخواست به‌صورت تیکت پشتیبانی برای HQ ثبت می‌شود.
5. HQ در بخش پشتیبانی درخواست را بررسی و تایید می‌کند.
6. پس از تایید، مجموعه و حساب مدیر ساخته می‌شود.

- `مدیر اصلی باید به درخواست ارجاع شود.`
- `مدیران ارجاعی باید از مدیران مجاز انتخاب شوند.`

1. کاربر وارد `/requests` می‌شود.
2. در صورت نیاز با فیلترها لیست را محدود می‌کند.
3. برای ثبت مورد جدید روی `ثبت درخواست` می‌زند.
4. عنوان، بخش، ارجاع‌گیرندگان، تاریخ، اولویت، توضیح و پیوست‌ها را ثبت می‌کند.
5. درخواست ذخیره و برای ارجاع‌گیرندگان ارسال می‌شود.
6. ارجاع‌گیرنده از مودال جزئیات، درخواست را تایید، رد یا ارجاع مجدد می‌کند.

#### سناریوی برداشت مستقیم

1. HQ یا مدیر روی `برداشت` می‌زند.

3. اگر جریان مستقیم باشد، تراکنش ثبت می‌شود.
4. پیام `برداشت ثبت شد.` نمایش داده می‌شود.

3. در صورت کارت‌به‌کارت، شماره کارت مقصد نمایش داده می‌شود.
4. کاربر پس از پرداخت، فرم تایید پرداخت و رسید را ثبت می‌کند.
5. تیکت مالی برای HQ ساخته می‌شود.
6. HQ در پشتیبانی عملیات واریز را انجام می‌دهد.

#### سناریوی برداشت مدیر از طریق پشتیبانی

1. مدیر روی `برداشت` می‌زند.
2. مقصد را `حساب بانکی` یا `کیف پول دیگر` انتخاب می‌کند.
3. اطلاعات مبلغ و مقصد را ثبت می‌کند.
4. تیکت فوری مالی برای پشتیبانی ساخته می‌شود.
5. HQ از پشتیبانی عملیات را تکمیل می‌کند.

- `Read`: مشاهده تنظیمات و کاربران مجاز
- `Update`: ویرایش نام سازمان، کدنوم، نام بخش، دسترسی‌ها
- `Delete`: حذف بخش‌ها

### اعتبارسنجی‌ها

- `بخش دسترسی معتبر نیست.`
- `فهرست بخش‌ها معتبر نیست.`
- `نام بخش تکراری است.`
- `نام سازمان الزامی است.`
- `کدنوم سازمان الزامی است.`
- `کدنوم سازمان تکراری است.`

### وابستگی‌ها

- ماژول کاربران
- فرم‌های درخواست، هزینه، سند
- دسترسی‌های منو

### سناریوی کامل

1. مدیر صفحه تنظیمات را باز می‌کند.
2. در صورت نیاز نام سازمان یا کدنوم را ویرایش می‌کند.
3. بخش‌های جدید اضافه یا قدیمی را حذف می‌کند.
4. روی یک بخش سیستمی مثل `گزارشات` یا `هزینه‌ها` می‌زند.
5. کاربران مجاز را در مودال انتخاب می‌کند.
6. تغییرات ذخیره می‌شود و روی منوها و دسترسی کاربران اثر می‌گذارد.

## 6.1 صفحه HQ

| آیتم | مقدار |
| --- | --- |
| نام صفحه | گزارشات HQ |
| Route | `/hq` |
| نقش مجاز | فقط حساب HQ |
| هدف | مدیریت کلان مجموعه‌ها، ساخت مجموعه، پایش تیکت‌های HQ و شاخص‌های سراسری |

### المان‌های صفحه

- کارت‌های خلاصه HQ
- جدول مجموعه‌ها
- فرم افزودن مجموعه
- جدول تیکت‌های HQ
- کارت‌های سگمنت نقش‌ها، پرداخت‌ها و تیکت‌ها

### CRUD

- `Create`: ساخت مجموعه جدید
- `Read`: مشاهده آمار، مجموعه‌ها، تیکت‌ها
- `Update`: انتخاب مجموعه برای scope سایر صفحات
- `Delete`: ندارد

### اعتبارسنجی‌ها

- `نام مجموعه الزامی است.`
- `کد مجموعه معتبر نیست.`
- `نام مدیر، نام کاربری و رمز عبور الزامی است.`
- `رمز عبور باید حداقل ۶ کاراکتر باشد.`
- `کد مجموعه قبلا ثبت شده است.`
- `نام مجموعه قبلا ثبت شده است.`
- `نام کاربری مدیر قبلا ثبت شده است.`
- `ایمیل مدیر قبلا ثبت شده است.`

### ارتباط با سایر صفحات

- انتخاب یک مجموعه در HQ باعث تغییر scope صفحه‌های:
- داشبورد
- کیف پول
- پشتیبانی
- گزارشات
- تنظیمات
- داده‌های bootstrap

### سناریوی کامل

1. کاربر HQ وارد `/hq` می‌شود.
2. مجموعه‌ای را از جدول انتخاب می‌کند.
3. سپس سایر صفحات را در scope همان مجموعه بررسی می‌کند.
4. در صورت نیاز از فرم `اضافه کردن مجموعه` سازمان جدید می‌سازد.

## 7. جمع‌بندی عملیات CRUD به تفکیک ماژول

| ماژول | Create | Read | Update | Delete |
| --- | --- | --- | --- | --- |
| ورود | نشست | - | - | خروج از نشست |
| ثبت‌نام | درخواست ثبت‌نام | وضعیت در پشتیبانی HQ | تایید توسط HQ | حذف مستقیم ندارد |
| درخواست‌ها | ثبت درخواست | لیست، جزئیات، پیوست | تایید، رد، ارجاع | ندارد |
| هزینه‌ها | ثبت هزینه | لیست، جزئیات، فاکتور | تایید، رد، ارجاع | ندارد |
| تاییدیه‌ها | ثبت سند، ثبت امضا | لیست، جزئیات، دانلود | تایید، رد، ارجاع، ویرایش امضا | ندارد |
| کیف پول | تراکنش یا تیکت مالی | مانده، ledger | اجرای برداشت/واریز | ندارد |
| پشتیبانی | تیکت، پیام، فیدبک | لیست، جزئیات | پاسخ، بستن، عملیات HQ | ندارد |
| کاربران | ایجاد کاربر | لیست، جزئیات | ویرایش، فعال/غیرفعال، پاداش/جریمه | حذف مستقیم ندارد |
| تنظیمات | ایجاد بخش، تعریف دسترسی | مشاهده تنظیمات | ویرایش | حذف بخش |
| HQ | ایجاد مجموعه | آمار و لیست | scope و ویرایش‌های HQ | حذف ندارد |

## 9. استثناها و نکات مهم آموزشی

1. صفحه تاییدیه‌ها و قابلیت امضا در منطق فعلی برای همه کاربران لاگین‌شده قابل دسترس است، اما داده‌های قابل مشاهده به داده‌های قابل مشاهده همان کاربر محدود می‌شود.
2. حذف واقعی برای کاربران، درخواست‌ها، هزینه‌ها و اسناد در رابط کاربری وجود ندارد.
3. غیرفعال‌سازی کاربر جایگزین حذف کاربر است.
4. در پنل HQ، انتخاب مجموعه از هدر بالایی روی چندین صفحه دیگر اثر scope دارد.
5. بخش‌ها در تنظیمات روی فرم‌های درخواست، هزینه، سند و کاربر اثر مستقیم دارند.
6. ارسال بسیاری از رویدادها با پیامک همراه است و موجودی کیف پول پیامک روی این رفتار اثر می‌گذارد.
7. برخی عملیات مالی مدیران به‌جای ثبت مستقیم، به صورت تیکت مالی برای HQ/پشتیبانی ساخته می‌شود.
8. برای تایید سند، وجود امضای دیجیتال معتبر الزامی است؛ مهر اختیاری است.
